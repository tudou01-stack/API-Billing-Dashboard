# 多 API 渠道余额统计仪表盘设计

## 目标与范围

交付一个可直接双击运行、可部署到 GitHub Pages 的单文件 `index.html`。页面使用原生 HTML、CSS 和 JavaScript，不依赖框架、构建工具、CDN 或后端。首版覆盖开发说明书全部必选需求及四项进阶功能：消费趋势图、渠道消费占比图、统计数据导出、页面内阈值提醒。

产品优先保证密钥安全边界透明、失败数据不污染统计、离线可用、移动端可操作，以及导入导出后的数据可恢复性。

## 技术路线

所有样式、逻辑和图表实现均内嵌在 `index.html`。图表使用原生 SVG，不加载第三方脚本。代码在单文件内按模块分区，每个模块通过稳定函数接口协作：

1. 常量与默认值：Schema 版本、存储键、限制值、平台元数据。
2. 工具模块：UUID、金额格式化、时间格式化、JSON 路径解析、URL 规范化、CSV 转义和下载。
3. 数据仓库：读取、迁移、校验、保存、导入、导出与容量裁剪。
4. 请求与适配器：构造 URL/请求头、代理模式、超时、错误分类、平台响应解析。
5. 业务模块：快照、差值消费、充值、手动调整、汇率换算、聚合、预警、日志。
6. 任务调度：并发上限为 3 的批量刷新/测试、自动刷新和连续失败跳过。
7. 视图与控制器：安全 DOM 渲染、事件委托、对话框、Toast、响应式导航和局部加载状态。

## 持久化数据

根对象沿用 `api_dashboard_v1`，并在说明书 Schema 上补齐实现所需字段。

### settings

- `lowBalanceThreshold`：全局低余额阈值，默认 10。
- `dailySpendAlertThreshold`：日消费页面内提醒阈值，默认 20。
- `autoRefreshEnabled`：自动刷新开关，默认关闭。
- `autoRefreshIntervalMinutes`：最少 5 分钟，默认 30。
- `defaultCurrency`：`USD` 或 `CNY`，默认 `USD`。
- `cnyPerUsd`：展示换算汇率，默认 7.2，并明确标注为参考值。

### channels

除说明书字段外增加：

- `customJsonPath`：自定义平台必填的余额字段路径。
- `newApiUserId`：OneAPI/NewAPI 可选请求头用户 ID。
- `lowBalanceThresholdOverride`：单渠道阈值覆盖，空值表示使用全局值。
- `lastBalance`、`lastCurrency`、`lastRefreshAt`：当前展示状态的持久化缓存。
- `lastAvailability`：DeepSeek 的 `is_available` 状态。
- `lastAdditionalBalances`：DeepSeek 非主币种余额，仅作附加展示。
- `lastTestResult` 支持 `untested`、`success`、`invalid_key`、`failed`。

API Key 保留在本地存储中以支持自动刷新；页面默认掩码，不在日志、DOM 属性、错误详情或 URL 中复制明文。

### snapshots、records 与 logs

- 每个渠道只保留最近 200 条成功快照。
- 只有成功得到有限数值余额才写入快照。
- 相邻成功快照余额减少时写入 `auto_diff`；增加时写入 `manual_recharge` 类型的充值流水，但不计消费；相等不写流水。
- 日志最多保留最近 1000 条，详情经过密钥脱敏。
- 金额以原始币种存储，只在聚合展示时换算。

导入时先在内存中解析、版本检查、字段归一化和关键类型校验；任何错误都不改动现有数据。成功导入后整体替换、保存并重绘。

## 页面与交互

### 信息架构

固定安全提示条位于页面顶部。主导航包含“总览”“流水与趋势”“日志”“设置”四个视图。

总览顶部显示统一币种下的总余额、累计花费、今日花费、本月花费四张摘要卡。其后提供批量刷新、全部测试、添加渠道和导入导出入口。渠道以响应式卡片网格呈现；窄屏单列，宽屏多列。

渠道卡片展示平台标签、余额与币种、健康状态、低余额提醒、最近更新时间、连接测试徽章和耗时，并提供刷新、测试、编辑、手动记账、删除操作。刷新与测试拥有独立 loading 状态，互不覆盖。

流水与趋势视图提供 7 天/30 天切换的 SVG 折线图、渠道消费占比 SVG 环图、筛选后的流水表格及 CSV/JSON 导出。

日志视图按时间倒序，支持渠道、级别和类别筛选，支持 JSON、纯文本导出及二次确认清空。

设置视图管理统一币种、参考汇率、全局低余额阈值、日消费提醒阈值、自动刷新开关与间隔，并提供完整备份导入导出和统计数据重置。

### 对话框

使用原生 `<dialog>` 实现新增/编辑渠道、手动记账、公共代理风险确认、删除确认、导出密钥警告、重置确认和导入选择。表单根据平台类型显示相关字段。DeepSeek 地址固定；OneAPI 输入根地址并自动拼接；自定义地址要求完整 URL 和 JSON 路径。

所有用户文本通过 `textContent`、`createElement` 和属性赋值渲染，不把用户输入拼入 `innerHTML`。仅固定、开发者控制的 SVG/模板片段可使用模板字符串。

## 请求、安全与代理

请求默认直连。Worker 与公共代理均按渠道配置，代理 URL 必须是 HTTP(S) URL。公共代理首次保存前展示包含实际代理域名的强警告，并要求用户明确确认。

请求统一使用 `AbortController`，10 秒超时。鉴权密钥只放入 `Authorization` 请求头；OneAPI 可追加 `New-Api-User`。代理目标 URL 通过占位符 `{url}` 或安全拼接方式传递，页面会说明代理实现需与配置格式匹配。

错误分为：

- `network`：网络失败、DNS、CORS 或主动超时；不写快照。
- `http`：非 2xx；401/403 在连接测试中单独映射为 `invalid_key`；不写快照。
- `parse`：响应非合法 JSON、平台结构非法或取值路径无数值；不写快照。
- `unavailable`：DeepSeek 返回 `is_available=false`；余额可展示并记录，但健康状态明确标为不可调用。

浏览器无法可靠区分所有网络/CORS/DNS 失败，提示文案会如实说明可能原因，不伪造精确诊断。

日志脱敏规则覆盖当前渠道 Key、Bearer 令牌样式和常见 `sk-` 令牌形式。导出完整备份前必须提示文件含明文密钥；日志和统计导出不包含 Key。

## 业务规则

批量操作使用通用任务池，并发数固定为 3。自动刷新只在页面可见时运行；页面隐藏或卸载时清除定时器，重新可见后恢复。自动任务跳过连续失败 3 次及以上的渠道，手动刷新仍允许重试；成功后失败计数归零。

统一汇总通过 `cnyPerUsd` 在展示时转换。若原币种不是 CNY/USD，则不纳入统一汇总并显示提示，避免静默使用未知汇率。

低余额阈值优先使用单渠道覆盖值。日消费超过阈值时显示页面内提醒，同一自然日同一阈值状态仅在当前页面会话中提示一次。

“重置统计”清除快照与流水，但保留渠道、设置和日志，并在确认框中建议先备份。“清空全部数据”不作为快捷入口，防止误操作。

## 可访问性与响应式

页面使用语义化标题、按钮和表单标签；状态不能只依赖颜色，同时配有文本/图标；键盘可访问所有主要操作；焦点样式清晰；动态结果通过 `aria-live` 通知。动画遵守 `prefers-reduced-motion`。

桌面端使用 12 列网格和侧边/顶部组合导航，移动端转为紧凑顶部导航和单列卡片。表格在窄屏允许横向滚动，主要操作按钮保持至少 44px 触控面积。

## 测试与验收

由于核心交付物必须是单个文件且无构建工具，自动化测试使用 Node 内置测试运行器，对从 `index.html` 暴露的纯函数测试钩子进行测试；测试文件不属于部署核心，可保留在仓库中用于维护。

测试覆盖：

- DeepSeek 单/多币种解析及不可用状态。
- OneAPI URL 拼接、额度换算、失败响应和可选用户头。
- 自定义 JSON 路径中的对象与数组索引。
- 网络、HTTP、解析错误不产生快照。
- 首次快照、消费差值、充值和零差值。
- 汇率换算与未知币种排除。
- 并发任务池峰值不超过 3。
- 每渠道 200 快照、全局 1000 日志裁剪。
- 日志与导出数据不泄露 Key。
- 导入校验失败时保持旧数据。
- 恶意渠道名称仅按文本显示，不执行脚本。

浏览器验收通过本地静态服务器完成，覆盖桌面和移动视口、空状态、表单条件字段、对话框、导航、图表、筛选、导入导出及控制台错误。网络类验收使用可控 mock `fetch` 模拟 200、401、403、500、超时和解析失败，不依赖用户提供真实付费 Key。

## 交付

仓库包含：

- `index.html`：唯一运行时交付物。
- `README.md`：使用、安全、GitHub Pages 与 Worker 部署说明。
- `worker-example.js`：纯转发 Cloudflare Worker 示例，不含任何密钥。
- `tests/`：自动化测试与浏览器验收辅助文件。
- `docs/`：设计与实施计划。

完成后运行自动化测试、静态安全扫描和桌面/移动浏览器验收，提交到 `main`，推送至 `git@github.com:tudou01-stack/API-Billing-Dashboard.git`。是否启用 GitHub Pages 取决于仓库权限与 GitHub 配置；若命令行凭据允许，将一并完成。
